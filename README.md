# 破阵 · Ayaya Breach

回合制解谜游戏。在棋盘上移动角色、推动方块，触发开关后到达出口。

## 怎么玩

1. 操作小人，在铺有地砖的区域移动。点相邻格或按方向键移动；点小人或按空格，原地等待一步。
2. 触发本局所有 A / B 开关，再走到出口。踩下 A 后，标 `A` 的炮台永久停火，标 `+A` 的炮台反而从此开始射击。
3. `X` / `Y` 是压板：人或木箱压在上面时，标同字母的炮台停火，离开就恢复。
4. 红线预告下一步的射击。炮台下方三个点依次表示它自己未来三步的节奏：实心射击，空心停火。
5. 木箱可以推动，也可以挡住火线；墙块不能推动。没有地砖的外围留白不属于可走区域。
6. 被击中、推错或想换思路，都可以撤回。没有计时器，也没有步数上限。

结算顺序固定：**移动 / 推方块 → 触发开关、按新位置判断压板 → 开火 → 判断是否到达出口**。走向墙或推不动方块，不消耗步数。开关、压板和掩体可以改变本步火力，所以红线按当前布局预览。

前两关会在相邻格标出“走过去会中炮”的叉号，等待按钮也会提示危险；之后默认不标，每一步是否安全要从红线和节奏点自己推算。“更多 → 标记”可以一直打开。

`↑ ↓ ← →` / WASD 移动，`Space` 等待，`Z` / `Backspace` 撤回，`R` 重来。菜单内暂停游戏快捷键；`Esc` 关闭菜单。手机可以点按或在棋盘上滑动。

## 关卡

| 章节 | 关卡                                 | 最短步数      |
| ---- | ------------------------------------ | ------------- |
| 节奏 | 错开一拍、连续通行、两种节奏、三门炮 | 9、11、16、19 |
| 开关 | 两个开关、交接、开关顺序             | 15、17、21    |
| 方块 | 推动掩体、压板、一箱两用、压住火线   | 8、14、20、22 |
| 综合 | 全部机关、最后一线                   | 28、32        |

关卡按顺序解锁：通关一关后开放下一关，已通关的随时可以重玩。每章只引入一个新概念，难度来自节奏、开关顺序、压板与掩体的取舍，而不是数值。最短步数显示在棋盘上方，是优化目标，不是通关门槛。

关卡由求解器约束筛选：节奏章不“等待”就无解；压板关去掉压板就无解；`+A` 炮台去掉后最短解会变短；教学关之外，每关最短解不超过 4 条，避免“绕来绕去都能过”。每关的标注都由完整状态空间的广度优先搜索验证，并写进测试。

## 分享关卡

“更多 → 复制关卡链接”会把当前棋盘编码进 URL hash（`#level=<base64url JSON>`），打开链接时在浏览器里用求解器校验有解并算出最少步数，不经过任何服务器。分享关卡不写入战役进度，通关后“返回”回到原来的棋局。JSON 格式：

```json
{ "t": "标题", "m": ["#######", "#S..E.#", "..."], "g": ["x,y,方向,节奏[,联动]"] }
```

方向为 `u` / `r` / `d` / `l`；节奏是 1–6 位 `0` / `1`；联动可选 `a` / `b`（踩下后停火）、`+a` / `+b`（踩下后启动）或 `x` / `y`（压板）。棋盘最大 10×10，最多 8 门炮台。

点按炮台可依次切换两步后、三步后、下一步的火力，也可在“更多”中选择。预览不推进棋局，按当前掩体和开关计算；实际操作后自动回到下一步。炮台下方三个点始终表示实际回合之后的三步，不随预览偏移。键盘聚焦炮台后可用 Enter 或空格切换预览。每关另有一条可展开的思路提示。

## 数据与前端

- 页面紧凑排列：标题与“步数 · 最少步数”一行，棋盘，一行关卡 / 撤回 / 等待 / 更多。手机上棋盘占满宽度（两侧 16px），桌面按窗口高度放大到最多 600px。通关后，等待原位变成下一关，结果以一行文字显示。预留反馈高度，避免操作时棋盘上下移动。
- 选关和设置使用同色背景，隐藏底下的棋盘，不显示遮罩卡片。重来、提示、主题和预览选项放在“更多”中，规则按需展开；每关开局在棋盘下方显示一句说明，第一步之后让位给反馈。
- 默认深色，可切换浅色，文字按钮、同一像素网格绘制的人物和物件。交错地砖标明可走区域，无格子描边，外围墙不绘制；墙、木箱、开关、门与火线均有独立的外观。原生 DOM 棋盘与 SVG 炮线，没有外部字体、账号、追踪或运行时依赖。
- 只使用浏览器 `localStorage` 保存当前关卡、操作记录、个人最佳、主题和标记开关，刷新可继续，撤回记录也会恢复。
- 损坏或不可用的存储不会阻止游玩。单次操作记录最多保存 4096 步，超过后仍可继续游玩并保存通关成绩，页面会说明当前棋局无法续存。
- v4 使用独立的存储键 `ayaya-breach-v4`，保留旧版存储，不把旧版塔防分数映射成新谜题成绩。
- 只在交互时更新界面，没有持续运行的动画循环。支持减少动态效果、键盘焦点、状态朗读与菜单焦点约束。

## 本地开发与验证

需要 Node.js 22：

```bash
npm ci
npm run dev
```

格式、规则测试、类型检查与生产构建：

```bash
npm run validate
```

Chromium 桌面和 iPhone WebKit 浏览器回归测试：

```bash
npx playwright install chromium webkit
npm run test:e2e
```

浏览器测试会启动独立的生产预览服务，验证全部关卡按顺序真实操作通关、续局、撤回、推掩体、压板、按序解锁、标记开关、分享链接、预览、主题、菜单、触控与多种屏幕尺寸。GitHub Actions 会在 Pages 部署前执行两套检查。

## 代码结构

- `src/engine.ts`：无副作用的规则与火线计算。
- `src/levels.ts`：分章节的固定地图与逐关提示。
- `src/solver.ts`：广度优先求解器；测试用它验证关卡，游戏用它给分享关卡校验有解、计算最少步数。
- `src/share.ts`：分享链接的编码与校验。
- `src/storage.ts`：校验、保存和回放当前棋局。
- `src/main.ts` / `src/style.css`：交互与响应式界面。
- `src/sprites.ts`：角色、方块、炮台、开关、压板和出口的 SVG 图形。
- `src/*.test.ts` / `e2e/game.spec.ts`：规则、存储与浏览器回归。

静态部署路径沿用 `/AyayaGame_1/`，无需后端。v4 改造说明见 [审查记录](docs/REVIEW.md)。
